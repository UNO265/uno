# KANENAZO LONG-FORM RETENTION GUIDELINE v2.0 — 롱폼 시청지속 지침

- **적용**: CASE #004부터 (롱폼 대본)
- **관계**: 기존 지침을 대체하지 않는다. [마스터 지침](KANENAZO_GUIDE.md), [대본 지침](KANENAZO_SCRIPT_GUIDE_v1.md), [v3 영상 지침](KANENAZO_GUIDE_v3.md), [성과 지침](KANENAZO_PERFORMANCE_v1.md)에 더해 적용한다.
- **양식**: 대본 전 설계는 [templates/question-chain-design.md](templates/question-chain-design.md), 대본 제출 전 검수는 같은 문서의 RETENTION CHECK.

기존의 다음 원칙은 모두 그대로 유지한다.

- 일본어 약 5,000자 전후
- 일본 시청자 기준의 자연스러운 일본어
- 일본 1차 자료 중심의 팩트체크
- MONEY FLOW
- CLUE
- 반전
- Documentary × Evidence × Motion Graphic
- 실제 자료와 숫자를 증거로 활용
- 가격 뒤의 비즈니스 구조를 발견하는 채널 정체성

CASE #004부터 추가로 적용할 가장 중요한 목표는 **「롱폼 영상의 시청지속률을 높이는 대본 구조」** 이다.

---

## 1. 왜 대본 구조를 수정하는가

CASE #001과 CASE #002의 초기 데이터를 분석한 결과, 두 영상 모두 평균 조회율이 약 34.7% 수준으로 나타났다.

현재 표본은 아직 작기 때문에 채널 방향이나 콘텐츠 스타일의 성공/실패를 단정하지 않는다. 따라서 다음 사항은 변경하지 않는다.

- KANENAZO의 채널 콘셉트
- MONEY FLOW
- 경제·비즈니스 미스터리 방향
- 약 5,000자 대본
- 일본 시장 중심
- Documentary Hybrid 스타일

대신 CASE #004부터는 **"시청자가 영상 중간에서도 계속 다음 내용을 봐야 할 이유가 있는가?"** 를 대본 설계의 핵심 기준으로 추가한다.

## 2. 기존 방식의 위험

다음과 같은 구조를 장시간 사용하지 않는다.

```
큰 질문 → 배경 설명 → 자료 설명 → 비용 설명 → 추가 설명 → 추가 설명 → 마지막에 정답
```

논리적으로 정확하더라도, 시청자가 영상 초중반에 이미 "아, 결국 이런 얘기구나."라고 결론을 예상하면 남은 영상은 '궁금해서 보는 내용'이 아니라 '추가 설명을 듣는 내용'이 된다. 롱폼에서는 이것이 중간 이탈의 원인이 될 수 있다.

따라서 **하나의 질문으로 영상 전체를 끌고 가지 않는다.**

## 3. QUESTION CHAIN 구조를 적용한다

CASE #004부터 KANENAZO 대본의 핵심 구조는 **QUESTION CHAIN**이다.

```
QUESTION A → 추적 → ANSWER A
→ 그 답에서 더 큰 QUESTION B 발생 → 추적 → ANSWER B
→ 새로운 모순 발견 → QUESTION C → 추적 → REVERSAL
→ FINAL MONEY FLOW → FINAL ANSWER
```

즉, **질문 → 보상 → 새로운 질문 → 보상 → 새로운 질문 → 큰 반전 → 최종 보상**의 구조다.

## 4. 질문만 계속 던져서는 안 된다

QUESTION CHAIN은 '떡밥을 계속 던지는 방식'이 아니다. 반드시 각 질문에 대한 실질적인 답을 제공해야 한다.

- **잘못된 방식**: 질문 A → 질문 B → 질문 C → 질문 D → 마지막에 모든 답
- **올바른 방식**: 질문 A → 답 A → 답 A 때문에 질문 B 발생 → 답 B → 답 B 때문에 예상 밖의 문제 발견 → 질문 C → 답 C + 반전

시청자는 2~3분마다 "하나를 알아냈다."라는 보상을 받아야 한다. 그리고 그 답 때문에 "그렇다면 이건?"이라는 새로운 궁금증이 자연스럽게 생겨야 한다.

## 5. INFORMATION REWARD 원칙

약 2~3분마다 의미 있는 정보 보상을 배치한다. 보상은 단순한 숫자 하나가 아니다. 다음 중 하나 이상이어야 한다.

- 질문에 대한 실제 답
- 예상과 다른 숫자
- MONEY FLOW의 일부 공개
- 공식 자료에서 발견한 사실
- 기존 상식을 뒤집는 구조
- 새로운 비용의 발견
- 새로운 수익원의 발견
- 시장의 변화
- 기업 전략의 차이
- 새로운 모순

시청자가 "그래서 뭐?"라고 느끼지 않도록 한다.

## 6. 질문의 강도는 점점 커져야 한다

같은 질문을 표현만 바꿔 반복하지 않는다.

- ✕ 왜 돈이 될까? → 정말 돈이 될까? → 그래도 왜 돈이 될까?
- ○ 왜 돈이 될까? → 그렇다면 가장 큰 비용은 무엇일까? → 그 비용을 감당하고도 어떻게 남길까? → 결국 이 사업의 수익을 결정하는 것은 무엇일까?

질문이 진행될수록 비즈니스 구조의 더 깊은 층으로 들어가야 한다.

## 7. 첫 번째 답을 너무 늦게 주지 않는다

최종 반전을 보호한다는 이유로 초반 5~7분 동안 답을 숨기지 않는다. 첫 번째 질문에는 비교적 빠르게 부분적인 답을 제공한다.

- **권장**: 첫 번째 의미 있는 보상은 약 2~3분 이내

예:

1. QUESTION: 「人がいないのに、なぜ儲かる？」
2. ANSWER: 인건비가 적다는 것은 실제 장점이다.
3. 그러나 바로 새로운 문제를 제시한다: 「でも、それだけでは説明できない。」
4. QUESTION 2: 「では、このビジネスで本当に大きなコストは何なのか？」

이런 식으로 이야기를 앞으로 진행시킨다.

## 8. 최종 반전 하나에만 의존하지 않는다

영상 마지막의 반전은 중요하다. 하지만 12~15분짜리 영상에서 마지막 반전 하나만 기다리게 만들지 않는다. 대신 **SMALL REVEAL → SMALL REVEAL → MID REVEAL → FINAL REVEAL** 구조를 사용한다.

예:

1. 첫 번째 발견: "인건비가 적다."
2. 두 번째 발견: "하지만 설비 비용이 크다."
3. 세 번째 발견: "가격보다 중요한 변수가 따로 있다."
4. 최종 발견: "이 사업은 사실 ○○의 사업이었다."

최종 반전은 앞에서 발견한 사실들을 하나로 연결해야 한다.

## 9. KANENAZO의 핵심 반전 방식

좋은 최종 결론은 "비싸다 / 싸다" 수준에서 끝나지 않는다. **처음에는 A처럼 보였지만, 돈의 흐름을 추적해 보니 실제로는 B라는 사업이었다**는 구조가 좋다.

- 처음: "사람이 없어서 돈을 버는 사업인가?"
- 최종: "실제로는 비싼 설비를 얼마나 효율적으로 회전시키느냐의 사업이었다."

이런 식으로 **PRICE MYSTERY**가 **BUSINESS MODEL DISCOVERY**로 발전해야 한다.

## 10. MONEY FLOW도 단계적으로 공개한다

MONEY FLOW를 영상 마지막에만 완성본으로 보여주지 않는다. 스토리 진행에 따라 일부씩 공개한다.

```
500円 → 水道・ガス・電気
500円 → 水道・ガス・電気 → 家賃
500円 → 水道・ガス・電気 → 家賃 → 設備投資・減価償却 → 管理
마지막: 전체 MONEY FLOW 완성
```

시청자는 영상 전체에서 돈을 함께 추적하고 있어야 한다.

## 11. 대략적인 롱폼 리듬

영상 길이를 억지로 맞추지 않는다. 약 12~15분 영상이라면 다음 구조를 참고한다.

| 시간 | 내용 |
|---|---|
| 0:00~0:35 | REALITY + CONTRADICTION + QUESTION 1 + CASE TITLE (**세부 순서는 11-1**) |
| 0:30~3:00 | MYSTERY 1 추적 + 첫 번째 INFORMATION REWARD |
| 3:00~6:00 | QUESTION 2 + EVIDENCE + MONEY FLOW 일부 + 두 번째 INFORMATION REWARD |
| 6:00~9:00 | QUESTION 3 + 더 깊은 BUSINESS STRUCTURE + MID REVEAL |
| 9:00~12:00 | 현재 시장 변화 + 예상 밖의 구조 + FINAL REVEAL |
| 마지막 구간 | FINAL MONEY FLOW + 최초 질문 회수 + KANENAZO ANSWER |

단, 이 시간은 절대적인 규칙이 아니다. 스토리가 11~12분에 완성된다면 억지로 15분까지 늘리지 않는다.

### 11-1. 도입부 0:00~0:35 (추가: CASE #003 재배치와 비교해 정함)

CASE #003은 점검 후 도입부를 재배치했다(질문 0:35 → 0:00, 타이틀 1:40 → 0:33). 이 방식과 v2.0 원안, 성과 지침 v1(9·10번)을 비교했다.

| 항목 | 성과 지침 v1 | v2.0 원안 | CASE #003 재배치 | **채택** |
|---|---|---|---|---|
| 제목의 질문 | 5~8초 | 30초 안 | **0초**(화면 글자 + 첫 음성) | **0~5초**, 글자와 음성 둘 다 |
| 대상 | 0~5초 | 5~10초 안 | 0초(질문과 같은 화면) | 0초(질문과 같은 화면) |
| 모순 | 10~20초 | 5~10초 안 | 5~12초 | **15초 안** |
| 가격·숫자(REALITY) | 0~5초 | 처음 | 12초(모순 뒤) | 모순의 재료면 모순과 함께, 아니면 모순 뒤 |
| 더 큰 질문 → QUESTION 1 | 20~30초 | 30초 안 | 20~28초 | **30초 안**, 2~3분 안에 답할 수 있는 질문으로 |
| CASE 타이틀 | 20~30초 | 없음 | 33초 | **35초 안** |
| 도입부의 설명·나열 | 금지 | 13번 | 비용 나열을 타이틀 뒤로, 6개 → 4개 | 타이틀 뒤로, 항목 4개 이하 |

**0초 질문을 택한 이유** (v2.0의 "30초 안"보다 엄격하게)

1. 시청자는 제목의 질문을 보고 눌렀다. 첫 화면에서 그 질문이 확인되지 않으면 "다른 얘기인가?" 하고 나간다(16번 THUMBNAIL → TITLE → HOOK의 흐름). "30초 안"이면 CASE #003 원본(질문 0:35)도 거의 통과해 기준이 되지 못한다.
2. 홈 피드의 미리보기는 소리 없이 재생된다. 질문이 0프레임에 **글자로** 있어야 소리 없이도 전달된다.
3. Shorts에서 질문을 앞으로 당기고 한 편 안에 답을 준 뒤 계속 시청이 16% → 28.6%로 올랐다(형식이 다르고 표본이 작아 방향만 참고한다).

**v2.0을 그대로 따르는 부분** (CASE #003보다 나은 점)

- 0초 질문은 **CORE MYSTERY**(제목의 질문)다. 이것을 끝까지 끌지 않는다. 30초 안에 **2~3분 안에 답할 수 있는 QUESTION 1**로 좁히고, 그 답에서 QUESTION 2가 나오게 한다(3·7번). CASE #003은 핵심 질문의 답을 11:41에 처음 주고, 그 사이는 부분 답(비용 목록 0:52, 수익 배분 목안 2:30, 1454円 3:10, CLUE 01 4:39)으로 이어 갔다. 부분 답이 2~3분 간격으로는 있었지만, "질문 → 답 → 새 질문"의 사슬로 설계된 것은 아니었다.

**CASE #003에서 얻은 도입부 주의점**

- 0초 질문 화면은 정지 화면으로 두지 않는다. 대상이 이미 움직이는 상태로 시작한다(성과 지침 25-1과 같은 원칙).
- 질문 직후에는 곧바로 모순으로 넘어간다. 질문만 두 번 되풀이하지 않는다.
- 타이틀 직후는 이탈이 쉬운 자리다. 화면이 빈 채 음성만 흐르는 구간을 두지 않는다(CASE #003 원본 1:46~2:18에 약 20초 있었음).

**검증**: 롱폼 30초 유지율을 [성과 기록](performance-log.md)에 적어 CASE #001·#002(질문 5~35초, 타이틀 1분 이후)와 CASE #003 재배치본, CASE #004를 비교한다. 두세 편에서 같은 방향이 나오기 전에는 이 기준을 확정으로 보지 않는다(20번).

## 12. 5,000자 규칙은 유지한다

CASE #004 이후에도 일본어 대본은 약 5,000자 전후를 기본으로 한다(권장 약 5,000~5,500자).

하지만 5,000자를 채우기 위해 같은 설명을 반복하지 않는다. 반복되는 문장이 있다면 삭제한다. 필요하다면 5,000자를 조금 밑돌더라도 **스토리 밀도, 시청지속률, 질문의 힘**을 우선한다.

## 13. 설명 구간을 짧게 만든다

한 가지 개념을 너무 오래 설명하지 않는다. 특히 시장 역사, 산업 배경, 기업 소개, 비용 항목, 통계 자료 등이 연속으로 이어지지 않도록 한다.

**DATA → MEANING → QUESTION** 구조를 사용한다.

1. 숫자 제시
2. 이 숫자가 무엇을 의미하는지 설명
3. 그 숫자 때문에 새로운 질문 발생

숫자를 보여주고 다음 숫자를 계속 보여주는 방식은 피한다.

## 14. 설명 뒤에는 반드시 변화가 있어야 한다

긴 설명 다음에는 다음 중 하나를 배치한다.

- 새로운 질문
- 새로운 숫자
- 실제 장면
- MONEY FLOW 변화
- CLUE
- 반전
- 비교
- 예상 밖의 사실

대본이 1~2분 이상 같은 톤의 설명으로만 진행되지 않도록 한다.

## 15. 시청자가 이미 답을 안다고 느끼는지 확인한다

대본 작성 중 계속 질문한다. **"지금 시점에서 시청자가 이미 최종 답을 예상할 수 있는가?"**

만약 그렇다면 단순히 답을 더 오래 숨기는 것이 아니라 더 깊은 질문을 만든다.

- 시청자: "인건비가 없으니까 돈을 버는 거네."
- 대본: "맞다. 그런데 문제가 있다. 이 사업에는 사람 대신 아주 비싼 기계가 필요하다."
- → 새로운 미스터리 발생.

이것이 QUESTION CHAIN이다.

## 16. HOOK와 본편이 연결되어야 한다

초반에 강한 질문을 던진 뒤 본편에서 전혀 다른 이야기를 하지 않는다.

- **THUMBNAIL → TITLE → HOOK → QUESTION 1**이 하나의 흐름이어야 한다.
- **QUESTION 1 → QUESTION 2 → QUESTION 3 → FINAL ANSWER**도 하나의 논리적 흐름이어야 한다.

## 17. 썸네일의 질문도 대본에서 회수한다

썸네일은 단순한 클릭 장치가 아니다. 썸네일에서 질문한 내용은 영상에서 반드시 다룬다. 제목과 썸네일은 서로 다른 역할을 한다.

| | 역할 |
|---|---|
| TITLE | 첫 번째 미스터리 |
| THUMBNAIL | 두 번째 궁금증 또는 더 압축된 질문 |
| VIDEO | 두 질문을 실제 MONEY FLOW로 해결 |

클릭을 위해 영상에서 다루지 않는 질문을 썸네일에 넣지 않는다.

## 18. 영상 길이보다 밀도를 우선한다

KANENAZO는 "길수록 좋은 롱폼"을 목표로 하지 않는다. 목표는 **"다음 내용을 계속 보고 싶은 롱폼"** 이다. 따라서 12분짜리 강한 영상이 16분짜리 반복 영상보다 낫다. 영상 길이는 스토리가 결정한다.

## 19. CASE #001~#003은 수정하지 않는다

CASE #001, #002, #003은 이미 제작/업로드된 영상으로서 비교 데이터로 활용한다. 이전 영상을 새로운 지침에 맞추기 위해 다시 수정하지 않는다.

CASE #004부터 새로운 QUESTION CHAIN 구조를 적용한다. 향후 #003의 시청 데이터가 충분히 쌓이면 그 결과를 CASE #005 이후 개선에 반영한다.

## 20. 데이터 해석 원칙

초기 조회수가 수백 회 수준일 때 하나의 영상만 보고 다음처럼 단정하지 않는다.

- "이 주제는 실패했다."
- "일본인은 이 스타일을 싫어한다."
- "Flat 2D가 문제다."
- "13분이 정답이다."
- "16분은 너무 길다."

여러 CASE에서 반복되는 패턴을 찾는다. 특히 확인할 것: Impressions, CTR, Average View Duration, Average Percentage Viewed, 첫 30초 retention, Audience Retention Curve, 급격한 DIP, 유지되는 구간, 상승하는 SPIKE, Traffic Source.

그리고 문제를 구분한다.

| 상황 | 가능성 |
|---|---|
| 노출 부족 | TOPIC 문제 |
| 노출은 있으나 CTR 낮음 | TITLE / THUMBNAIL / TOPIC PACKAGING |
| 클릭은 되지만 초반 이탈 | HOOK |
| 초반은 유지되지만 중간 이탈 | STORY / QUESTION CHAIN / 반복 설명 |
| 후반 이탈 | 결론이 너무 늦거나, 이미 답을 예상했을 가능성 |

## 21. CASE #004부터 대본 작성 전 반드시 설계할 것

대본을 바로 작성하지 않는다. 먼저 아래 구조를 만든다([양식](templates/question-chain-design.md)).

| 항목 | 내용 |
|---|---|
| CORE MYSTERY | 이 영상의 최초 질문은 무엇인가? |
| EXPECTED ANSWER | 일반 시청자가 처음 예상할 답은 무엇인가? |
| QUESTION 1 | 첫 번째 질문 |
| REWARD 1 | 2~3분 안에 제공할 첫 번째 답 |
| QUESTION 2 | 첫 답 때문에 발생하는 새로운 질문 |
| REWARD 2 | 두 번째 발견 |
| QUESTION 3 | 더 깊은 비즈니스 질문 |
| MID REVEAL | 중간 반전 |
| FINAL REVEAL | 처음의 예상과 실제 구조가 어떻게 다른가? |
| MONEY FLOW | 소비자가 낸 돈이 어디로 이동하는가? |
| FINAL ANSWER | 영상 시작의 질문에 한 문장으로 어떻게 답할 것인가? |

**이 설계를 먼저 사용자에게 제시하고, 방향이 확정된 후 5,000자 대본을 작성한다.**

## 22. 대본 작성 중 반드시 던질 질문

각 구간을 작성할 때 스스로 확인한다.

- "시청자는 지금 무엇이 궁금한가?"
- "방금 그 궁금증에 대한 보상을 줬는가?"
- "그 답 때문에 새로운 질문이 생겼는가?"
- "앞으로 2분을 더 볼 이유가 있는가?"
- "지금 설명은 새로운 사실인가, 아니면 앞에서 말한 내용을 반복하고 있는가?"
- "이 부분을 삭제해도 이야기가 이해된다면 삭제하는 것이 더 낫지 않은가?"

## 23. 최종 RETENTION CHECK

최종 대본 제출 전 반드시 검수한다([양식](templates/question-chain-design.md#retention-check)).

- [ ] 0~5초에 대상과 제목의 질문이 보이고 들리는가? (화면 글자 + 음성, 11-1)
- [ ] 15초 안에 모순이, 30초 안에 2~3분 안에 답할 QUESTION 1이, 35초 안에 CASE 타이틀이 나오는가?
- [ ] 2~3분 안에 첫 번째 정보 보상이 있는가?
- [ ] 첫 번째 답 이후 새로운 질문이 생기는가?
- [ ] 질문이 점점 깊어지는가?
- [ ] 2~3분마다 의미 있는 변화가 있는가?
- [ ] 같은 설명이 반복되지 않는가?
- [ ] MONEY FLOW가 단계적으로 진행되는가?
- [ ] 중간에도 최소 하나의 반전이 있는가?
- [ ] 시청자가 4~5분 만에 최종 결론을 모두 예상할 수 없는가?
- [ ] 최종 반전이 앞의 CLUE들을 하나로 연결하는가?
- [ ] 처음의 PRICE MYSTERY가 BUSINESS MODEL DISCOVERY로 발전하는가?
- [ ] 제목의 질문을 실제로 해결하는가?
- [ ] 썸네일의 질문도 영상에서 회수하는가?
- [ ] 마지막에 최초 질문에 명확하게 답하는가?
- [ ] 불필요하게 영상 길이를 늘리지 않았는가?

## 24. 최종 목표

CASE #004부터 KANENAZO 대본의 목표는 "끝까지 답을 숨기는 것"이 아니다. 목표는 **"계속 답을 주면서, 더 큰 질문을 만드는 것"** 이다.

시청자가 영상을 보는 동안 다음 사고 흐름을 경험하게 한다.

> "왜?" → "아, 그렇구나." → "그런데 그러면?" → "아, 그래서였구나." → "잠깐, 그렇다면?" → "아! 결국 이 사업은 이런 구조였구나."

이 리듬이 KANENAZO 롱폼의 새로운 핵심 구조다.

## 25. 한 문장으로 기억할 것

KANENAZO CASE #004 이후의 대본은 **「질문 하나를 15분 동안 끄는 영상」이 아니라, 「답을 하나씩 얻을수록 더 큰 미스터리가 열리는 영상」** 으로 만든다.
