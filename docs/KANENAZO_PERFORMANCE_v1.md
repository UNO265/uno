## 1. 현재 가장 중요한 진단

가장 명확한 병목은 **"콘텐츠 안쪽"보다 "콘텐츠 입구"**에 있다.
- **롱폼**: 노출은 발생하지만 CTR이 낮다.
- **Shorts**: Shorts 피드 노출은 발생하지만 약 84~85%가 넘긴다.

**개선 우선순위**: 1. TOPIC → 2. TITLE → 3. THUMBNAIL → 4. FIRST 5~30 SEC → 5. STORY → 6. VISUAL → 7. 세부 애니메이션

애니메이션만 개선해서 낮은 클릭률이 해결될 것이라고 가정하지 않는다.

## 2. 핵심 성공 공식

영상은 4단계를 통과해야 한다.
1. **STOP**: 스크롤 또는 탐색을 멈춘다.
2. **CLICK**: 제목과 썸네일을 보고 누른다.
3. **STAY**: 첫 30초를 본다.
4. **CONTINUE**: 답을 알기 위해 계속 본다.

"이 영상이 좋은가?"보다 먼저 "멈추게 하는가? 누르게 하는가? 30초를 보게 하는가? 답을 기다리게 하는가?"를 확인한다.

## 3. 주제 선정 — TOPIC

**공식**: 身近なモノ × お金の謎 × MONEY FLOW × 今起きている変化

좋은 주제는 제목을 보기 전부터 대상이 익숙해야 한다.

**우선순위가 높은 대상**: 음식, 편의점, 영화관, 호텔, 배달, 택배, 자판기, 주차장, 카페, 구독 서비스, 무료 서비스, 할인, 생활용품, 관광, 교통

**주제 선정 질문**
1. 일본인이 자주 보는가?
2. 가격을 알고 있는가?
3. 가격에 의문을 가질 수 있는가?
4. 돈의 흐름을 추적할 수 있는가?
5. 예상과 다른 반전이 있는가?
6. 현재 일본의 변화와 연결되는가?

6개 중 여러 개가 약하면 제작 전에 주제를 다시 검토한다.

## 4. 제목 — TITLE

제목은 "내용 설명"이 아니다. 제목 자체가 하나의 미스터리여야 한다.

**구조**: [익숙한 대상] + [구체적인 가격/숫자] + [돈에 관한 질문]
- 「ラーメン一杯1000円。店には、いくら残る？」
- 「映画館のポップコーン700円。原価はいくら？」
- 「送料無料。送料は誰が払っている？」

좋은 제목은 제목만 읽어도 시청자의 머릿속에 질문이 생긴다.

### 4-1. 제목의 3가지 기준: SEO · 짧게 · 후킹 (추가)

제목은 정해진 틀에 끼워 맞추지 않는다. 4번의 구조(대상 + 숫자 + 질문)도 후킹 방법의 하나일 뿐이다. 모든 제목은 다음 **세 가지를 동시에** 만족해야 한다.

**① SEO: 검색되는 말로 쓴다**
- 사람들이 실제로 검색하는 표기를 쓴다: 「ダイソー」「セリア」(DAISO·Seria 아님), 「100均」(100円ショップ보다 우선), 「ラーメン」「コンビニ」 등.
- 가장 중요한 검색어를 **맨 앞**에 둔다.
- 화면 속 표기는 그대로 둬도 된다. 제목·설명·해시태그에서만 검색 표기를 쓴다.
- 해시태그는 주제 키워드 1~2개(#100均, #セリア 등). 아직 검색되지 않는 채널명 해시태그(#KANENAZO)는 설명란에 둔다.

**② 짧게**
- 목표는 **20자 안팎**, 길어도 30자 이내. 모바일 목록과 Shorts 화면에서 잘리지 않게 한다.
- 설명·수식어를 빼고, 검색어와 후킹만 남긴다.

**③ 후킹: 누르고 싶은 이유를 하나 만든다**
다음 중 **하나**를 고른다(여러 개를 섞지 않는다).
- 의문: 「100均、なぜ100円で儲かる？」
- 대립: 「ダイソーvsセリア：100円は守れる？」
- 역설·반전: 「売れているのに、儲からない」
- 의외의 숫자: 「ラーメン1000円、店に残るのは？」
- 숨은 구조: 「送料無料、払っているのは誰？」

후킹은 영상 내용과 일치해야 한다. 영상이 주지 않는 답(「どっちが勝つ？」의 승자 등)을 암시하지 않는다. Shorts는 그 편 안의 답과 맞아야 한다(24-1).

**흔한 표현 주의**: 「〜の正体」「考察」「検証」「徹底解説」은 검색 점수는 높아도 피드에서 눈에 띄기 어렵다. 쓰더라도 후킹이 따로 있을 때만 쓴다.

**제목 점수 도구에 대해**
- vidIQ류 도구의 점수는 대부분 **검색 최적화(키워드) 점수**이고, 실제 클릭률을 예측한 값이 아니다. ① SEO를 확인하는 참고로 쓴다.
- ② 짧음과 ③ 후킹은 도구 점수로 판단하지 않는다. 최종 판단은 YouTube Studio 「テストと比較」(제목 A/B 테스트)와 실제 CTR로 하고, 결과는 [성과 기록](performance-log.md)에 남긴다.

**예**

| 대상 | 제목 | 글자 수 | SEO | 후킹 |
|---|---|---|---|---|
| CASE #001 본편 | 100均、なぜ100円で儲かる？ | 15 | 100均 | 의문 |
| CASE #001 Shorts ③ v2 | ダイソーvsセリア：100円は守れる？ | 19 | ダイソー・セリア | 대립 |
| CASE #002 본편 | ラーメン1000円、店に残るのは？ | 16 | ラーメン | 의외의 숫자 |

## 5. 제목에서 피할 것

- 너무 긴 설명형 제목
- 경제 전문용어
- 결론을 제목에서 공개
- 질문이 두세 개 들어간 제목
- 「徹底解説」「完全解説」「知らないと損」 같은 범용 표현의 남용

KANENAZO는 자극적인 문구보다 **"이상한 돈의 구조" 자체**가 클릭 이유가 되어야 한다.

## 6. 썸네일 — THUMBNAIL

현재 최우선 개선 대상 중 하나. 썸네일은 영상 내용을 요약하지 않고 **"한 가지 의문"**만 전달한다.

**구성**: 1 OBJECT + 1 NUMBER + 1 QUESTION
- 예: 팝콘 이미지 + 「700円」 + 「原価は？」. 끝. 썸네일에서 설명하지 않는다.

## 7. 썸네일 텍스트

- 가능하면 2~7자 정도의 강한 일본어 표현을 우선 검토한다.
- 예: 「利益は？」「原価は？」「誰が払う？」「なぜ安い？」「残るのは？」「0円？」
- 제목과 썸네일은 같은 문장을 반복하지 않는다.
  - TITLE = 상황 설명 + 미스터리
  - THUMBNAIL = 질문 압축

## 8. 썸네일 가독성

모바일 기준으로 판단한다. PC에서 예쁘게 보이는지는 두 번째 문제다.

체크 항목:
- 핵심 물체가 즉시 보이는가?
- 숫자가 즉시 읽히는가?
- 질문이 즉시 읽히는가?
- 작은 글씨가 없는가?
- 장식이 너무 많지 않은가?
- 배경과 대상이 명확하게 분리되는가?

아주 작게 축소해도 **"무엇 + 얼마 + 무슨 질문"**인지 보여야 한다.

## 9. 첫 5초 — FIRST 5 SEC

첫 5초에는 설명하지 않고, 현상과 질문을 보여 준다.

- **구조**: REAL OBJECT → PRICE → QUESTION
- **예**: 팝콘이 쏟아진다 → 「700円」 → 잠깐 정지 → 「原価は？」
- 첫 질문은 가능하면 5~8초 이내에 나오게 한다.
- **롱폼은 CASE #004부터 [시청지속 지침 v2.0 11-1](KANENAZO_RETENTION_v2.md#11-1-도입부-000035-추가-case-003-재배치와-비교해-정함)을 우선한다**: 0~5초에 대상 + 제목의 질문(글자 + 음성), 15초 안에 모순, 30초 안에 QUESTION 1, 35초 안에 CASE 타이틀.

## 10. 첫 30초 — HOOK

첫 30초는 "정보 전달"이 아니라 **"미스터리 생성"** 구간이다.

| 시간 | 내용 |
|---|---|
| 0~5초 | 대상 + 가격 |
| 5~10초 | 첫 질문 |
| 10~20초 | 상식과 현실의 충돌 |
| 20~30초 | 더 큰 질문 / CASE TITLE |

**금지**: 긴 인사, 채널 소개, 역사 설명, 비용 항목 긴 나열, 통계부터 시작, 결론 설명

시청자가 아직 궁금하지 않은 상태에서 설명부터 하지 않는다.

## 11. 30초 이후 — OPEN LOOP

하나의 질문에 답하면 바로 다음 질문이 생겨야 한다.

- **나쁜 구조**: 질문 → 설명 → 설명 → 설명 → 설명 → 결론
- **좋은 구조**: 질문 A → 부분 답 → 그런데? → 질문 B → 증거 → 반전 → 질문 C → MONEY FLOW → FINAL ANSWER

답을 계속 미루기만 하지 않는다. 작은 답을 계속 주면서 더 큰 질문을 만든다.

## 12. 60~90초 규칙

약 60~90초마다 "지금 새로운 이유가 생겼는가?"를 확인한다.

새로운 이유: 새로운 질문, 놀라운 숫자, 반전, 증거, 비교, CLUE, 현실 장면, MONEY FLOW 변화. **단순히 화면만 바꾸는 것은 새로운 이유가 아니다.**

## 13. CLUE의 역할

CLUE는 시청자에게 **보상**을 준다. "여기까지 본 결과 이것을 알아냈다."

- 예: CLUE 01 「1000円は、売上であって利益ではない。」
- 반드시 **CLUE → BUT → NEXT QUESTION**으로 이어진다.
- CLUE가 영상 흐름을 멈추는 요약 카드가 되어서는 안 된다.

## 14. 시각적 단조로움 개선

CASE #001 → #002에서 정보 시각화는 개선되었다. 그러나 설계상 다른 화면(A / C / D / G)도 모두 같은 방식으로 표현하면 시청자에게는 "같은 화면"으로 느껴질 수 있다.
- 아이보리 배경 + 플랫 그래픽 + 남색 글씨 + 노란 포인트

CASE #003부터는 정보 타입뿐 아니라 **VISUAL TEXTURE**를 관리한다.

## 15. VISUAL TEXTURE

다음 질감을 섞는다. 한 가지 질감이 긴 시간 영상을 지배하지 않게 한다.

| 질감 | 역할 |
|---|---|
| REAL | 실제 세계 |
| DOCUMENT | 실제 근거 |
| DATA | 숫자 |
| GRAPH | 변화 |
| FLAT 2D | 보이지 않는 구조 |
| MONEY FLOW | 돈의 이동 |
| DARK | 질문 |
| TYPOGRAPHY | 핵심 문장 |

## 16. FLAT 2D의 역할 변경

- **기존**: Flat 2D가 영상이고, 실사가 보조였다.
- **CASE #003 이후**: 다큐멘터리가 영상이고, Flat 2D가 설명 도구다.

**Flat 2D가 가장 잘하는 것**: 돈의 흐름, 원가 구조, 공급망, 수수료, 객단가, 회전율, 이익 구조, 플랫폼 구조

실제로 볼 수 있는 것은 가능하면 현실 자료를 먼저 검토한다.

## 17. 움직임보다 대비

계속 움직이지 않는다.

- **좋은 리듬**: REAL → 정지 → 질문 → 움직임 → DATA → 무음 → REAL
- **예**: 「1000円。」 정지. 「でも――」 그 순간 돈이 갈라진다.

한 번의 의미 있는 움직임이 10개의 장식 애니메이션보다 낫다.

## 18. 자막 개선

모든 내레이션을 하단 박스 자막으로 반복하지 않는다.

화면 자체가 자막인 것: 「8855億円」, 「利益は？」, 「売れている。でも、残らない。」, CLUE, MONEY FLOW, 그래프의 숫자, 중요 문장.

자막은 필요할 때만 표시한다. 목표: **"움직이는 PPT" 느낌을 줄인다.**

## 19. 실사/B-ROLL

실사는 장식이 아니라 **REALITY RESET** 역할을 한다.

특히 다음 순간에 쓴다: 오프닝, 새 챕터 시작, 긴 설명 뒤, 추상적인 숫자 뒤, 결론 직전.

가능한 경우 현장음도 짧게 살려서, 영상이 다시 현실 세계로 돌아온다는 느낌을 만든다.

## 20. EVIDENCE

실제 근거가 있는 자료만 EVIDENCE라고 표시한다.
- 해당 자료: 공식 통계, 정부 자료, 기업 IR, 공식 가격, 공식 메뉴, 공식 발표
- 근거 없는 그래픽에는 EVIDENCE 라벨을 붙이지 않는다.
- 자료의 그래프 이미지를 그대로 가져오지 않는다. 수치를 확인하고 KANENAZO 방식으로 재구성한다.
- 저작권과 사용권은 별도로 확인한다.

## 21. 숫자

숫자는 읽는 정보가 아니라 **사건**으로 만든다.

예: 市場規模 8855億円 → 過去最大 → 그런데 356億円 → 171億円 → 「売れている。でも、残らない。」

숫자가 다음 질문을 만들어야 한다.

## 22. FINAL ANSWER

제목에서 질문했다면 영상 마지막에 반드시 답한다. 답이 단일 숫자가 아닐 수도 있지만, 그럴 때도 "정답이 없는 것"처럼 말하지 않는다.

- **나쁜 표현**: 「店によって違います。」
- **좋은 표현**: 「答えは100円でも200円でもない。店によって違う。なぜなら、同じ1000円でも出ていくお金が違うからだ。」

**답을 먼저 주고, 이유를 설명한다.**

## 23. MONEY FLOW

FINAL ANSWER 직전 또는 직후에 가능하면 MONEY FLOW를 완성한다.

- **흐름**: 소비자가 낸 돈(PRICE) → 어디로 갔는가? → 무엇이 남았는가?
- 영상 초반에 나온 가격이 마지막에는 완전히 다른 의미로 보이게 해야 한다. 이것이 KANENAZO의 시그니처다.

## 24. Shorts는 롱폼과 별도 설계

> **Shorts는 [KANENAZO_SHORTS_v1](KANENAZO_SHORTS_v1.md)(쇼츠 지침서)이 우선한다.** 아래 24~28번은 그 바탕이 된 기록으로 남긴다. 특히 마지막 화면은 반복 재생 대신 본편 썸네일 화면으로 바뀌었다(쇼츠 지침 2번).

Shorts를 "롱폼의 짧은 버전"으로 생각하지 않는다. Shorts는 별도의 콘텐츠다. 초기 데이터에서 약 84~85%가 스와이프했으므로, 가장 먼저 개선할 것은 **FIRST FRAME**이다.

### 24-1. 롱폼과 연계하되, 한 편으로 완결한다 (추가)

한 롱폼에서 Shorts 여러 편을 만들 때도, 각 Shorts는 **처음 보는 사람이 그 한 편만 보고 만족할 수 있어야** 한다. Shorts 피드 시청자는 채널도 본편도 모른다.

**원칙: 1질문 1답 + 다리 한 줄**
1. **Shorts 하나 = 질문 하나.** 첫 1~3초에 던진다.
2. **답은 Shorts 안에서 완전히 준다.** 본편 내용을 아끼지 않는다. 「答えは本編で」처럼 숨긴 답으로 유도하지 않는다.
3. **본편과는 "다른 궁금증" 한 줄로 잇는다.** 이 Shorts의 답을 준 뒤, 본편이 다루는 더 큰 질문을 한 줄 던진다.
   - 예: 「同じ100円ショップでも、戦い方は正反対。」(답) → 「では、そもそも100円で、なぜ儲かるのか。」(다리)
   - 다리 문장이 첫 문장으로 자연스럽게 이어지면 반복 재생에도 유리하다.
4. **본편 광고처럼 보이는 요소를 줄인다.**
   - 계속 떠 있는 「CASE #00X」 머리말이나 「続きは本編で」 엔드카드는 쓰지 않는다. 채널 표시는 작은 로고 정도로 한다.
   - 본편 연결은 YouTube의 「関連動画」 기능과 고정 댓글에 맡긴다.
5. **본편에도 답이 없는 질문으로 끝내지 않는다.** 본편으로 넘어간 시청자가 실망하지 않게 한다.

## 25. Shorts 첫 프레임

0~1초 안에 이해되어야 한다.

- **피한다**: 작은 캐릭터, 긴 문장, 넓은 빈 공간, 작은 일본어, 천천히 등장하는 제목
- **권장**: 큰 제품 + 큰 숫자 + 아주 짧은 질문 (예: 팝콘 크게 + 「700円」 + 「原価は？」. 끝.)

### 25-1. 첫 1초 규칙 — 계속 볼지는 0.5~1.5초에 정해진다 (추가)

「계속 시청함 / 이탈함」은 영상 전체의 질이 아니라 **첫 1초**에서 갈린다. CASE #002 Shorts ①(28.6%)을 프레임 단위로 보면, 0~1.3초 동안 화면에는 丼 + 「1000円」만 있고, 질문은 음성으로 1.3초에야 나왔다. 제목에 있는 후킹(「5年で141に？」)이 **영상의 첫 1초에는 없었다.** 계속 본 사람은 제목·주제에 끌린 사람뿐이었다고 본다.

앞으로 모든 Shorts는 아래 다섯 가지를 지킨다.

1. **0프레임에 질문이 글자로 떠 있다.** 소리를 끄고 첫 화면만 봐도 "무엇이 궁금한 영상인지" 알 수 있어야 한다. 질문은 페이드인하지 않고 0프레임부터 보인다.
2. **첫 음성은 질문이나 충돌로 시작한다.** 「ラーメン、一杯1000円。」처럼 누구나 아는 사실(전제)로 시작하지 않는다. 전제는 질문 안에 넣거나 질문 뒤로 보낸다.
   - ✕ 「ラーメン、一杯1000円。」→「その原価は？」
   - ○ 「1000円のラーメン、原価は5年でどれだけ上がった？」
3. **2초 안에 답의 윤곽을 보여 준다.** 「100 → ?」처럼 답이 곧 나온다는 신호를 준다. 3초까지 설명·출처로 시작하지 않는다.
4. **0프레임부터 움직인다.** 김만 피어오르는 정지 화면은 사진으로 읽혀 넘겨진다. 줌인, 가격표가 찍히는 동작, 막대가 올라가는 동작처럼 **큰 움직임**이 첫 프레임에 이미 진행 중이어야 한다.
5. **숫자 하나보다 두 숫자의 충돌.** 「1000円のまま」 vs 「原価141」처럼 첫 화면에서 모순을 보여 주면 더 오래 붙잡는다.

**화면 배치**: 핵심 글자·숫자는 세로 화면의 가운데 영역(위에서 약 20~65%)에 둔다. 아래쪽 약 25%와 오른쪽 가장자리는 제목·버튼 UI가 가린다. 화면 아래 절반을 비워 두지 않는다.

**제목과 첫 1초를 일치시킨다**: 제목의 후킹 문구(의문·숫자)가 0프레임 글자와 첫 음성에 그대로 들어가야 한다. 제목에만 후킹이 있고 영상 첫 1초에 없으면, 피드에서 제목을 보지 못한 사람은 넘긴다.

**확인 방법**: 렌더 뒤 0초·0.2초·0.5초·1.0초·1.5초 프레임을 한 장으로 뽑아(`scripts/shorts_sheet.mjs`와 같은 방식) 소리 없이 본다. 이 다섯 장만 보고 질문을 말할 수 없으면 다시 만든다.

## 26. Shorts 시작 구조

| 시간 | 화면 | 음성 |
|---|---|---|
| 0초 | PRICE + QUESTION을 **함께** (글자) | 질문으로 시작 |
| 0~2초 | 답의 윤곽(「100 → ?」, 두 숫자의 충돌) | 질문 끝 |
| 2~7초 | SURPRISE | 의외의 답 |
| 7초 이후 | EXPLANATION | 이유 |

예: 화면 「700円」+「原価は？」 / 음성 「700円のポップコーン、原価はいくら？」 → 「実は、問題はトウモロコシの値段ではない。」 → 본론

※ 이전 판은 0~1초 PRICE → 1~3초 QUESTION이었다. 가격만 있는 1초가 "아는 얘기"로 읽혀 넘겨졌으므로(25-1), 가격과 질문을 0초에 함께 보여 주는 것으로 바꿨다.

첫 3초 안에 영상을 봐야 하는 이유를 만든다.

## 28. Shorts에서 확인할 핵심 데이터

**채널의 주력은 롱폼이다. Shorts의 목적은 롱폼으로 시청자를 보내는 것이다.** (2026-09 확정)

- **1차 지표: 본편 유입.** Shorts별 「関連動画」 링크 클릭 수(Studio → 해당 Shorts → 분석 → 「関連動画のクリック」/「관련 동영상 클릭」)와, 본편의 트래픽 소스 중 「Shorts 피드」 조회수.
- **2차 지표: Viewed vs Swiped Away.** 스와이프되면 본편까지 갈 기회도 없으므로 계속 추적한다.
- 조회수가 많아도 본편 유입이 없으면 성공으로 보지 않는다. 채널 시청자층 통계도 Shorts 조회가 섞이므로, 롱폼 판단에는 콘텐츠 유형을 「동영상」으로 거른 값을 쓴다.
- **올리는 순서**: 본편을 먼저 공개한다 → 각 Shorts에 「関連動画」로 본편을 지정해 공개한다(본편 공개 전에는 지정할 수 없다). 한 CASE의 Shorts는 하루 이틀 간격으로 나눠 공개해 본편으로 가는 입구를 여러 번 만든다.
- **내용**: 24-1(한 편 완결 + 본편이 답하는 다른 질문 한 줄)을 지킨다. 다리 한 줄은 본편의 제목·썸네일 질문과 같은 방향이어야 클릭한 사람이 실망하지 않는다.
- 당분간 단순 조회수보다 **Viewed vs Swiped Away**와 **본편 유입**의 변화를 함께 확인한다.
- 한 영상에서 모든 요소를 동시에 바꾸지 않는다.
  - Shorts #1: 기존 방식
  - Shorts #2: 첫 프레임만 변경
  - Shorts #3: 첫 질문까지 변경
- 이렇게 무엇이 실제로 영향을 주는지 확인한다.

## 31. 섣불리 판단하지 않는다

채널은 초기 단계다. 50회, 700회, 800회 같은 작은 표본만으로 "이 스타일은 실패", "일본인은 이 영상을 싫어한다", "이 주제는 안 된다"라고 결론 내리지 않는다.

초기 데이터는 **"가설"**을 만드는 데 쓴다. 반복되는 패턴이 나타나면 그때 전략에 반영한다.
