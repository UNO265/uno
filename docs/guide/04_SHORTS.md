# 04 SHORTS — 쇼츠

> 롱폼이 주력이고 쇼츠는 병행해서 꾸준히 올린다. 쇼츠의 목적은 **궁금하게 만들어 롱폼으로 보내는 것**(본편 유입)과 **채널 성장**이다.
> 데이터 기록: [성과 기록](../performance-log.md)의 Shorts 표(편별 구독자 칸은 쓰지 않는다, 사용자 결정).

## SH1. 한 편의 구조: 작은 답 + 본편의 질문

```
0초   질문(글자 + 첫 음성) ── 스와이프를 막는다
~20초 작은 질문에 대한 답 ── "이 채널은 답을 준다"
끝    본편의 질문 + 본편 썸네일의 물체 ── 궁금증을 본편으로
```

1. **작은 질문 하나에 쇼츠 안에서 답한다.** 「答えは本編で」로 숨기지 않는다(답을 못 받으면 본편도 누르지 않는다). 처음 보는 사람이 그 한 편만으로 만족해야 한다.
2. **본편의 최종 답·MID REVEAL은 말하지 않는다.** 쇼츠의 답은 본편의 앞쪽 보상(REWARD 1~2)이나 숫자 하나.
3. **마지막 한 줄 = 본편 제목 또는 썸네일 질문과 같은 말.** 본편에 답이 있는 질문만.
4. 광고처럼 보이는 요소 금지: 「CASE #00X」 머리말, 「続きは本編で」「リンクから」, 엔드카드. 연결은 「関連動画」와 고정 댓글에 맡긴다. 왼쪽 위 작은 로고만.

## SH2. 끝: 반복 재생 (사용자 결정)

- 마지막 컷(약 0.8~1초)은 **본편 썸네일과 같은 물체 + 본편의 질문(글자)**.
- 마지막 0.5초에 **0프레임과 똑같은 그림**으로 바뀐다(위치·크기·회전까지 맞춤 — 첫 컷의 그림을 함수로 만들어 마지막 컷에서 f=0으로 그린다).

## SH3. CASE마다 3편

| 종류 | 내용 |
|---|---|
| **① 입구** | 본편 제목의 질문 → 본편 REWARD 1 → 본편 썸네일 질문 |
| **② 의외의 숫자** | 본편의 공식 숫자 하나(시장 규모·점포 수·평균 단가 등) → 본편 썸네일 질문 |
| **③ 돈의 흐름** | 본편 MONEY FLOW의 한 단계 → 본편 제목의 질문 |
| 실험 | 다음 주제 후보 검증, 첫 1초 방식 검증(한 번에 한 요소만) |

- 세 편은 서로 다른 숫자·REWARD를 쓴다. 본편의 그림과 공식 숫자를 다시 쓰고 새 조사는 하지 않는다.
- **목표**: 최근 10편 평균 조회수 **1,000회 이상**(사용자 목표).
- **간격**: 본편 공개 당일 ①, 이후 2~3일 간격으로 ②·③. 본편이 없는 주에도 과거 CASE의 ②·③으로 끊기지 않게.
- 최근 10편 평균이 두 달 넘게 1,000회 아래면 첫 1초·주제 선택을 먼저 고친다. 関連動画 클릭이 계속 0에 가까우면 끝 화면과 설명란 첫 줄을 바꿔 실험한다.

## SH4. 첫 1초 (계속 볼지는 0.5~1.5초에 정해진다)

1. **0프레임에 질문이 글자로**(페이드인 없음). 소리를 끄고 첫 화면만 봐도 무엇이 궁금한 영상인지 알 수 있다.
2. **첫 음성은 질문이나 충돌**(아는 사실·전제로 시작하지 않는다). ✕「ラーメン、一杯1000円。」 ○「1000円のラーメン、原価は5年でどれだけ上がった？」
3. **2초 안에 답의 윤곽**(「100 → ?」, 두 숫자의 충돌).
4. **0프레임부터 큰 움직임**이 진행 중(정지 화면은 사진으로 읽혀 넘겨진다).
5. 숫자 하나보다 **두 숫자의 충돌**.

- 쇼츠 제목 = 0프레임 글자와 같은 문장 + `#Shorts`.
- 확인: 렌더 뒤 0 / 0.2 / 0.5 / 1.0 / 1.5초 프레임을 소리 없이 보고 질문을 말할 수 있어야 한다(`scripts/shorts_sheet.mjs`).

## SH5. 화면과 소리

- 1080×1920 전용 설계(롱폼 그래픽을 가운데 넣지 않는다). 제품·숫자는 크게, 글씨는 짧게.
- 핵심 글자·숫자는 세로 위치 약 **20~65%**. 아래 약 25%와 오른쪽 가장자리는 UI가 가린다. 의미를 전하는 글자 44px 이상(출처 30px).
- 길이 25~40초, 대본 6~8컷. 내레이션 1.3배(`narration.py --rate 1.3`). BGM은 본편 무드와 주제 선율로 새로 작곡. 실사 없음(CASE #010까지).

## SH6. 올리는 순서와 문구

1. **본편을 먼저 공개**(関連動画는 공개된 영상만 지정 가능) → 쇼츠마다 「関連動画」에 본편 지정.
2. 설명란 첫 두 줄: 쇼츠의 답 한 줄 → 본편의 질문 한 줄 → `【本編】` + URL. 고정 댓글에도 본편 링크. 해시태그 3~5개, 크레딧·출처는 끝에.

## SH7. 지표

| 순위 | 지표 | 보는 곳 |
|---|---|---|
| 1 | 関連動画 클릭 수·클릭률 | Studio → 쇼츠 → 분석 |
| 1 | 본편 트래픽 소스 중 「Shorts 피드」 조회수 | Studio → 본편 → 도달범위 |
| 2 | 계속 시청 / 스와이프 | 쇼츠 분석 → 참여도 |
| 3 | 조회수·평균 시청 시간 | 참고 |

- 조회수가 많아도 본편 유입이 없으면 성공으로 보지 않는다. 롱폼 판단에는 콘텐츠 유형을 「동영상」으로 거른 값을 쓴다.
- 아직 정하지 않은 것: 내레이션 속도(1.3배), 쇼츠 길이의 최적값.
