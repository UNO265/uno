# 01 PLANNING — 주제·조사·제목·썸네일

> 우선순위: **TOPIC → TITLE → THUMBNAIL → 첫 30초 → STORY → VISUAL → 세부 애니메이션.** 애니메이션만 고쳐서 낮은 클릭률이 해결된다고 가정하지 않는다.
> 영상이 통과해야 할 4단계: **STOP**(멈춘다) → **CLICK**(누른다) → **STAY**(30초를 본다) → **CONTINUE**(답을 기다린다).

## P1. 주제 선정

| 기준 | 확인할 것 |
|---|---|
| ① 身近さ | 일본인이 생활에서 자주 보고, **가격을 알고 있는가** (음식·편의점·영화관·호텔·배달·택배·자판기·주차장·카페·구독·무료 서비스·할인·생활용품·관광·교통…) |
| ② 謎 | 직관과 현실 사이에 모순이 있는가, 가격에 의문을 가질 수 있는가 |
| ③ MONEY FLOW | 소비자가 낸 돈을 추적할 수 있는가 |
| ④ 반전 | 예상과 다른 답이 있는가 |
| ⑤ NOW | 지금 일본의 변화(物価高·円安·人件費·物流費·インバウンド·人手不足·DX·手数料 등)와 연결되는가 |

| ⑥ **인접 장르** (2026-10-02 추가) | 이 주제가 **붙을 큰 YouTube 장르**(예: #002 라멘 → 음식점 밀착 다큐)와 **그 장르 시청자가 원하는 답**(예: 점주 입장의 구체적 숫자)을 함께 적는다. 도달은 인접 장르가, 만족은 그 답이 정한다([분석](../retention-001-005.md)). 썸네일의 대상도 그 장르의 시각 언어로 고른다 |

여러 개가 약하면 제작 전에 다시 검토한다. 로드맵은 [case-roadmap.md](../case-roadmap.md).

## P2. ANSWER CARD (주제 게이트, CORE C2)

주제·제목을 정하기 **전에** 채운다. 못 채우면 제목을 바꾸거나 주제를 버린다. 양식: [question-chain-design](../templates/question-chain-design.md) 0번.

| 항목 | 내용 |
|---|---|
| 제목 질문 / 답의 형식 | 숫자 / 이유 / 예·아니오 / 누구 |
| 공개 자료로 말할 수 있는 답 | 한 문장 |
| 출처 | 1차 자료 3개 |
| 공개되지 않는 부분과 처리 | 첫 1분 안에 말함 + 범위로 좁히는 방법 |
| 처음 답하는 시각 | 영상의 1/3 안 |

- ✕ 「ラーメン1000円、店に残るのは？」(가게별 이익 비공개, 범위도 1차 자료로 만들기 어렵다)
- ○ 「送料無料、本当に無料？」(「無料ではない」로 초반에 답하고 뒤에서 "누가·어떻게"를 판다)

## P3. 조사와 깊이

**조사 우선순위**: 정부·공공기관 → 기업 공식 자료 → IR·결산 → 업계 단체 → 주요 경제 매체 → 전문 매체 → (보조) 해외 자료.
**조사할 것**: 시장 규모, 가격 변화, 기업·비용·수익·유통 구조, 업계 변화, 소비자 행동, 전략, 최근 변화.

- 조사한 것을 모두 넣지 않는다(100개 중 가장 강한 30~40개). 대신 **분량이 모자라면 조사를 더 한다**(C3).
- 조사 결과는 `docs/case00X-research.md`에 사실 번호(예: H1~H25)·기준 시점·출처와 함께 적는다. 1차 자료는 ★. 작업 환경에서 원문이 막혀 검색 요약으로 확인한 숫자는 표시해 두고, **공개 전에 원문 확인**을 사용자에게 요청한다.
- **깊이 점검(필수)**
  1. 제목 질문을 일본어로 검색한다. 1위·요약 답이 우리 최종 답과 같으면 그 답은 **중간 보상**으로 내리고, 최종 답은 한 층 더 깊은 구조(누가·왜·얼마·언제부터 바뀌었나)로.
  2. **ONLY-HERE FACTS 3개 이상**을 설계표에 출처와 함께 적는다.
  3. 공개되지 않은 숫자는 「イメージ」로 넘기지 않는다. "왜 공개되지 않나", "무엇으로 범위를 좁히나"를 장면으로 만든다.
  4. 최종 답 한 문장을 듣고 "그건 알고 있었다"고 할 사람이 많으면 1번부터 다시.

## P4. 제목

**세 가지를 동시에** 만족한다.

1. **SEO**: 실제 검색 표기(「100均」「ダイソー」「ラーメン」…)를 쓰고, 가장 중요한 검색어를 **맨 앞**에. 해시태그는 주제 키워드 1~2개, 채널명 해시태그는 설명란에.
2. **짧게**: 목표 **20자 안팎**, 최대 30자.
3. **후킹 하나**: 의문 / 대립 / 역설·반전 / 의외의 숫자 / 숨은 구조 중 **하나만**.

- 참고 구조: [검색되는 대상] + [구체적인 가격·숫자] + [돈에 관한 질문]. 틀에 끼워 맞추지는 않는다.
- **숫자를 묻는 제목**(「いくら残る？」「原価は？」「利益は？」「何%？」)은 공개 자료로 그 숫자(범위·평균·사례)를 줄 수 있을 때만.
- **질문의 형식 = 답의 형식**: 최종 답 첫 문장에서 같은 형식으로 답한다. 설계표에 "제목이 약속한 형식"과 "영상의 답 첫 문장"을 나란히 적는다.
- **피할 것**: 긴 설명형, 전문용어, 결론 공개, 질문 두세 개, 「徹底解説」「完全解説」「知らないと損」「〜の正体」「考察」「検証」 남용, 【驚愕】·！·「最強」 같은 자극어, 영상이 주지 않는 답의 암시.
- **제목 추천 도구(vidIQ Suggestions)**: 점수는 검색 키워드·길이·자극어 규칙 점수이고 CTR 예측이 아니다. 채널 조회의 95~98%는 홈·추천에서 오므로(검색 약 1.4%) 영향이 작다. 추천 목록은 **검색어 후보**로만 써서 설명란 첫 두 줄·해시태그에 넣고, 결정은 YouTube Studio 「テストと比較」(A/B)와 실제 CTR로 한다. 「経営」「副業」처럼 다른 목적의 시청자를 부르는 말은 쓰지 않는다.
- 제목은 영상 0초의 질문·타이틀 카드와 같은 문장이다.

## P5. 썸네일

> **썸네일 이미지는 사용자가 직접 만든다**(2026-09-28). 우리는 설계안(물체·숫자·질문)과 점검만 제안한다.
> **예외 — A/B 테스트(2026-10-02, 사용자 결정)**: 이미 공개한 영상은 사용자 썸네일(현재, GPT 제작)과 **Claude가 만든 썸네일**을 YouTube 「테스트 및 비교」로 겨룬다. 결과는 [성과 기록](../performance-log.md)에 남기고, 이긴 쪽의 특징을 이 P5에 반영한다.

- **구성**: 1 OBJECT + 1 NUMBER + 1 QUESTION. 요약하지 않고 "한 가지 의문"만.
- **텍스트**: 2~7자의 짧은 질문. 제목과 같은 문장을 반복하지 않는다(TITLE = 상황 + 미스터리, THUMBNAIL = 압축된 두 번째 질문).
- **답을 숨기고 궁금증은 키운다(필수)**: 최종 답·MID REVEAL·CLUE 핵심어를 쓰지 않는다(물음표를 붙여도 답이면 불가 — 예: #003 「本命は売店？」). 썸네일 질문은 **답이 영상 앞·중반(REWARD 1~3)에 있는 두 번째 궁금증**. 제목이 "왜"를 물으면 썸네일은 "얼마·누가·어디"처럼 다른 각도로.
- **궁금증 만드는 법(하나만)**: 익숙한 숫자 + 모르는 숫자 / 0이나 극단적인 숫자 / 두 숫자의 충돌 / 빈칸.
- **점검**: "썸네일만 보고 결론을 맞힐 수 있는가?" → 있으면 다시. "썸네일 질문의 답이 영상 몇 분 몇 초에 있는가?" → 적을 수 없으면 다시. 영상이 다루지 않는 질문은 넣지 않는다.
- **가독성(모바일 기준)**: 가로 약 160px로 줄여도 「무엇 + 얼마 + 무슨 질문」이 즉시 보이는가. 작은 글씨·과한 장식 없음, 배경과 대상 분리.
- 좋은 예: #004 「1155億円 · 何を買ってる？」, #005 「0円 · 誰が払う？」, #007 「15,000円 · 誰が決めた？」.
