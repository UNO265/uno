# 05 DATA — 업로드와 성과 기록

> 양식: [upload-checklist](../templates/upload-checklist.md), 기록: [performance-log](../performance-log.md).

## D1. 업로드 준비 (`docs/case00X-upload.md`)

- 제목(확정안 + A/B 후보), 썸네일 설계(사용자 제작), 설명란(질문 → 결론 먼저 → 무엇을 추적하는지 → 챕터 → 출처 → ※계산·이미지 표시 → 크레딧 → 해시태그), **PROMISE AUDIT 표**(C9).
- 챕터는 첫 챕터 0:00, 각 10초 이상.
- 크레딧: `ナレーション：VOICEVOX:雀松朱司` / `BGM・効果音：オリジナル（音源：FluidR3_GM SoundFont / MIT License）`.
- 작업 환경에서 원문을 열지 못한 출처는 목록으로 남기고, **공개 전에 사용자가 원문을 확인**한다.

## D2. 업로드 후 기록 (CASE마다)

- **롱폼**: 노출수, CTR, 조회수, 평균 시청 시간, 평균 시청률, **30초 유지율**(Studio 「주요 순간 → 인트로」), 시청지속 그래프, 트래픽 소스, 일본 시청자 비중, 구독 전환, **좋아요 비율(싫어요 대비)**.
- **좋아요 비율이 채널 평균보다 20%p 이상 낮으면** 먼저 제목·썸네일의 약속과 답이 어긋났는지 본다(근거: #002 38.9% vs 평균 82.0%).
- **시청지속 그래프 × 장면**: 급격한 하락 시간·유지·상승 시간을 **장면 번호와 실제 내레이션·화면**과 함께 기록한다. 상승 구간을 곧바로 성공한 장면으로 단정하지 않는다(반복 시청·구간 이동·표본 크기).
- 제목 A/B(「テストと比較」) 결과, 비판 댓글(C10)도 기록한다.

## D3. 해석 순서

| 상황 | 먼저 볼 것 |
|---|---|
| 노출 부족 | 테스트 단계인지 / 주제 수요(TOPIC) |
| 노출은 있는데 CTR 낮음 | 제목 / 썸네일 / 주제 포장 |
| CTR은 괜찮은데 첫 30초 이탈 | HOOK / 제목과 내용의 일치 / 오프닝 속도(S4) |
| 첫 30초는 괜찮은데 중간 이탈 | 설명 반복 / 질문 부족 / 같은 질감 반복 / 전개 속도 |
| 후반 이탈 | 결론이 늦거나 이미 예상됨 / 답 뒤 요약(S8) |
| 끝까지 보지만 구독·다음 영상이 약함 | 채널 정체성 / 다음 CASE 연결 / 엔딩 |

## D4. 섣불리 판단하지 않는다

- 수백 회 수준의 한 영상으로 "이 주제는 실패", "일본인은 이 스타일을 싫어한다", "13분이 정답" 같은 결론을 내지 않는다. 초기 데이터는 **가설**을 만드는 데 쓰고, **두세 편에서 같은 방향**이 나오면 전략에 반영한다.
- 한 영상에서 모든 요소를 동시에 바꾸지 않는다(무엇이 영향을 줬는지 알 수 있게).
