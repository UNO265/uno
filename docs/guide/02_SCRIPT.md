# 02 SCRIPT — 질문 사슬과 대본

> 양식: [question-chain-design](../templates/question-chain-design.md)(설계 + RETENTION CHECK). 점검 도구: `video/scripts/retention_check.py`.
> **대본을 쓰기 전에 질문 사슬 설계를 사용자에게 먼저 제시하고, 확정된 뒤에 쓴다**(C7).

## S1. 형식

- **분량**: 4,000자 이상, 5,000자 내외(C3). 모자라면 조사를 더 한다. 반복 금지.
- **일본어가 기준**: 일본인이 YouTube 다큐로 들었을 때 자연스러운 문장. 짧게, 내레이션 호흡으로. 번역투·논문체·과한 유튜버 말투·과장 감탄 금지.
- 「重要なのは〜」「つまり〜」「ここで〜」「しかし――」「では――」는 필요한 곳에서만(과하면 AI 대본처럼 들린다).
- **출력**: 초안은 일본어 내레이션(+ 필요하면 한국어 검토용 번역). 사용자가 **"최종 대본"** 을 요청하면 일본어 내레이션만 **코드 블록 하나**로(설명·번역·출처·연출 지시 제외).
- **컷 파일**: `cases/case00X/cuts.json`(컷 ID·문장 `/` 구분·lead/tail·pace/tone/pitch·clue) + `script.txt`.

## S2. QUESTION CHAIN (핵심 구조)

```
QUESTION A → 추적 → ANSWER A
→ 그 답에서 더 큰 QUESTION B → 추적 → ANSWER B
→ 새로운 모순 → QUESTION C → 추적 → MID REVEAL
→ FINAL MONEY FLOW → FINAL ANSWER
```

- **하나의 질문으로 영상 전체를 끌지 않는다.** 질문만 계속 던지고 마지막에 모든 답을 주는 방식 금지. 각 질문에 **실질적인 답**을 주고, 그 답 때문에 "그렇다면?"이 생기게 한다.
- **질문은 깊어진다**: 표현만 바꾼 반복(왜 비싸? → 정말 비싸? → 그래도 왜?) 금지. 새 질문은 **더 깊은 사업 구조나 새 모순**을 드러내야 한다. 이미 이해한 내용을 다시 설명하는 것은 보상이 아니다.
- **제목 질문의 답은 영상의 1/3 안에**(C2). FINAL REVEAL은 그 뒤의 비즈니스 구조: **처음엔 A처럼 보였지만, 돈을 따라가 보니 B라는 사업이었다.**
- **반전은 여러 번**: SMALL REVEAL → SMALL REVEAL → MID REVEAL → FINAL REVEAL. 최종 반전은 앞의 CLUE들을 하나로 연결한다.
- **"지금 시청자가 최종 답을 예상할 수 있나?"** → 그렇다면 답을 더 숨기지 말고 더 깊은 질문을 만든다.
- 원가만으로 설명하지 않는다(「原価が安い＝暴利」 금지). 핵심은 **그 가격이 비즈니스 구조에서 어떤 역할을 하는가**.
- 가능하면 후반에 **「今、何が変わっているのか？」** 를 연결한다(억지로 최신 이슈를 붙이지는 않는다).
- **설계 항목**: CORE MYSTERY / EXPECTED ANSWER / QUESTION 1 / REWARD 1(2~3분 안) / QUESTION 2 / REWARD 2 / QUESTION 3 / MID REVEAL / FINAL REVEAL / MONEY FLOW 단계 / FINAL ANSWER(한 문장).

## S3. INFORMATION REWARD — 2~3분마다

보상은 다음 중 하나 이상: 질문의 실제 답, 예상과 다른 숫자, MONEY FLOW 일부 공개, 공식 자료의 사실, 상식을 뒤집는 구조, 새 비용·새 수익원의 발견, 시장 변화, 기업 전략의 차이, 새 모순. "그래서 뭐?"가 되지 않게 한다.

- **60~90초마다 "새로 볼 이유가 생겼는가"** 확인(새 질문·놀라운 숫자·반전·증거·비교·CLUE·MONEY FLOW 변화). 화면만 바꾸는 것은 새 이유가 아니다.
- **REWARD 뒤 부연은 두 문장까지.** 그다음은 새 질문·근거·숫자·MONEY FLOW·반전으로 넘어간다(근거: #002 2:40~3:05 53% → 42%).
- **DATA → MEANING → QUESTION**: 숫자 하나 → 의미 → 그 숫자로 생긴 질문. 숫자를 연속으로 나열하지 않는다. 숫자는 정보가 아니라 **사건·증거**다.
- **설명보다 발견**: 답부터 말하지 않고 시청자가 함께 발견하게. ✕「客単価を上げるために販売しています」 ○「チケットの枚数を増やせないとしたら――売上を増やすには？」
- **한 컷에서 45초 넘게 설명하지 않는다.** 길어지면 새 숫자·질문·화면 전환을 넣는다.
- 긴 설명 뒤에는 반드시 변화(새 질문·숫자·장면·MONEY FLOW 변화·CLUE·반전·비교).

## S4. 첫 30초 (CASE #008부터, 사용자 확정 2026-09-28)

**공감 → 위화감 → 질문 → 약속·예고 → 타이틀.** 근거: #006·#007 점검(시청자와의 관련이 약함, 약속·예고 없음, 타이틀+비공개 설명이 30초 직후에 몰려 약 20초간 새 정보 없음), 잘되는 해설·다큐 채널의 공통 틀.

| 시간 | 역할 | 쓰는 법 |
|---|---|---|
| **0~3초** | **공감 장면** | 「あなた」·지금·**구체적인 값과 장소**(일반론 금지). 화면은 0프레임부터 움직이고, **제목의 질문을 글자로** 화면 위에(소리 없는 홈 미리보기용) |
| **3~8초** | 마음속 말 | 시청자가 속으로 하던 말. **공감은 8초 안에 끝** |
| **8~15초** | 위화감·의외의 사실 | 「でも」 + **1차 자료 숫자 하나** |
| **15~20초** | 질문(= 제목) | 제목 질문을 음성으로 |
| **20~27초** | 약속 + 예고 | 답이 몇 분에 나오는지 + 중반의 가장 강한 사실 하나를 예고(답·MID REVEAL은 예고하지 않음, 약속한 시각을 지킨다) |
| **27~30초** | 타이틀 | **2~3초.** 「今日のカネナゾは――」 + 제목 |
| **30~34초** | 비공개 한 줄 | **한 문장**: 「○○は非公表。だから決算で追う」 → 곧바로 첫 1차 자료 숫자 |

- **순서 규칙**: 공감만 하고 끝나면 "맞아" 하고 나간다. 위화감이 반드시 바로 뒤에.
- **금지**: 인사·채널 소개·역사·비용 나열·통계부터 시작·결론 설명, 「〜を見てみよう」 같은 연결 문장.
- **타이틀 직후**: 첫 문장은 구체적인 내용(가설·첫 사실·숫자). 「まずは〜追いかけてみよう」「見ていこう」 금지(근거: #002 타이틀 뒤 75% → 56%).
- 예: #007 「出張でホテルを予約したら1泊1万5千円。会社の上限は8878円なのに。」 / #006 「ガチャの前で500円玉を入れる。昔は100円だったのに。」
- (CASE #004~#007은 옛 틀: 0~5초 제목 질문, 15초 모순, 30초 QUESTION 1, 35초 타이틀.)

## S5. 롱폼 리듬 (참고, 길이를 억지로 맞추지 않는다)

| 시간 | 내용 |
|---|---|
| 0:00~0:35 | S4 |
| ~3:00 | QUESTION 1 추적 + REWARD 1(제목의 답) |
| 3:00~6:00 | QUESTION 2 + EVIDENCE + MONEY FLOW 일부 + REWARD 2 |
| 6:00~9:00 | QUESTION 3 + 더 깊은 구조 + MID REVEAL |
| 9:00~12:00 | 현재의 변화 + 예상 밖의 구조 |
| 마지막 20% | S8 회수 구간 |

## S6. MONEY FLOW — 처음부터 단계적으로

- 소비자가 낸 돈을 실제로 추적한다(예: 1000円 → 食材 → 人件費 → 家賃 → 光熱費 → 残るお金).
- **마지막에 갑자기 요약으로 나오지 않는다.** 초반(가격) → 중반(돈이 빠져나감) → 후반(어디로 갔나) → FINAL(처음 가격의 의미가 바뀜). 설계표에 단계별 공개 시각을 적는다.

## S7. CLUE

- 보통 3~5개, **내용이 개수를 정한다**(억지로 쪼개지 않음). 중요한 발견이 있을 때만.
- CLUE = "여기까지 알아낸 것" 한 문장(보상). 반드시 **CLUE → BUT → NEXT QUESTION**. 흐름을 멈추는 요약 카드가 되지 않게.
- CLUE 번호와 내레이션이 충돌하지 않게 대본 단계에서 함께 검증. 「一つ目/二つ目」보다 「まず」「もう一つ」「さらに重要なのが」.

## S8. 마지막 20%와 엔딩

- 마지막 20%는 **회수 구간**: FINAL MONEY FLOW → 핵심 반전(한두 문장) → 최종 답 → 고정 엔딩(C8). 새 설명을 길게 추가하지 않는다. 단, 분량 기준을 채우는 **새 사실**(현재의 변화 등)은 회수 구간 **앞**에 둔다.
- 앞에서 설명한 비용·편익·흐름을 **내레이션으로 다시 나열하지 않는다** → FINAL MONEY FLOW **화면**으로 보여 주고 내레이션은 한 문장.
- **요약 표현 금지**: 「振り返ると」「ここまで見てきた」「今回わかったこと」「まとめると」「おさらい」「整理すると」.
- **최종 답(「答えは…」)에서 고정 엔딩까지 60초 이내**(근거: #002 답 뒤 요약 11:30~13:16에 39% → 17%, 전체 최대 하락).
- 최종 답은 **답 먼저, 이유는 뒤에**. 결론은 요약이 아니라 해결: 「つまり――」 → 핵심 구조(CLUE 합체·MONEY FLOW 완성) → 최종 문장 → 엔딩.
- 새로운 질문만 던지고 끝내지 않는다.

## S10. 세 시점 점검 — 설득력 (CASE #008부터, 사용자 확정 2026-09-29)

근거: #007 시청 피드백 — 논리·팩트는 좋지만 **공급자(회사) 설명에 치우쳤다**. 소비자의 가격 저항, 업계의 구체적 대응, 시청자에게 남는 선택지가 약했다. 질문 사슬 설계 때 세 칸을 채우고, 대본에서 **각각 공개 자료가 있는 한두 컷**으로 넣는다(없으면 조사를 더 한다. 추측으로 채우지 않는다, C4).

| 시점 | 대본에 들어갈 것 | #007에 빠졌던 예 |
|---|---|---|
| ① 사는 사람 | 값이 올랐는데 **왜 그래도 사는가**(편리함·대안 없음) + **어디서 저항하는가**(덜 산다·다른 데서 산다·포기한다). 조사·통계로 | 1.5만엔을 받아들이는 이유 / 여행 포기 |
| ② 파는 쪽의 대응 | 비용·인력 문제를 짚으면 **업계가 실제로 하는 원가 절감·효율화**를 구체적 사례로(무엇을·누가·언제) | 셀프 체크인, 청소 로봇, 연박 청소 생략 할인 |
| ③ 시청자에게 남는 것 | "앞으로"에 더해 **시청자가 쓸 수 있는 선택지**(대체재·싸게 사는 방법·수요가 옮겨 가는 곳). 조언은 사실(값 차이·제도)에 기대고, 특정 상품 광고가 되지 않게 | 출장객·내국인의 대처, 캡슐호텔·민박으로의 분산 |

- 위치: ①은 첫 답(REWARD 1) 뒤 1/3 안쪽, ②는 문제를 짚은 바로 뒤, ③은 "앞으로" 구간(마지막 20%의 회수 구간 **앞**, S8).
- 분량(C3)을 채우는 첫 후보로 쓴다. 반복·요약으로 늘리지 않는다.

## S9. 대본 제출 전 검사

1. **retention_check.py**: 컷 분할 직후(시각은 글자 수로 추정)와 최종 음성 뒤(실측)에 실행한다.
   ```bash
   cd video && python3 scripts/retention_check.py --case case00X
   ```
   | 점검 | 규칙 |
   |---|---|
   | 첫 문장이 질문인가 / 타이틀 35초 이내 | S4 |
   | 타이틀 직후 25초의 전환 문장 | S4 |
   | 45초를 넘는 컷 | S3 |
   | 마지막 20%의 요약 표현·재나열 / 최종 답 → 엔딩 60초 | S8 |

   경고는 문장을 보고 판단한다. (#008부터 첫 문장이 공감 장면이면, 20초 안에 제목 질문을 말하는지로 검사한다.)
2. **반복 설명 검사**: 문단마다 "앞에서 설명했나 / 새 사실·해석이 있나 / 지워도 이해되나" → 새 정보 없고 지워도 되면 압축·삭제(질문을 회수하는 짧은 반복은 허용).
3. **RETENTION CHECK**: [양식](../templates/question-chain-design.md#retention-check)의 체크박스.
4. **사실 검사**: 근거 없는 원가·이익률 없음, 売上/利益 혼동 없음, 과거 자료의 현재화 없음, 기업 의도 단정 없음, 계산·이미지·보도 표시(C4).
5. **세 시점(S10)**: 사는 사람 / 파는 쪽의 대응 / 시청자에게 남는 것 — 각각 근거 있는 컷이 있는가?
6. **작성 중 스스로 묻기**: 시청자는 지금 무엇이 궁금한가? 보상을 줬나? 그 답에서 새 질문이 생겼나? 앞으로 2분을 더 볼 이유가 있나? 지워도 이해된다면 지우는 게 낫지 않나?
