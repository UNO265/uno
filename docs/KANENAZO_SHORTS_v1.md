# KANENAZO SHORTS GUIDELINE v1.0 — 쇼츠 지침서

- **적용**: CASE #004 쇼츠부터(아직 제작 전인 편)
- **관계**: Shorts에 관해서는 이 문서가 [성과 지침](KANENAZO_PERFORMANCE_v1.md) 24~28번보다 우선한다. 첫 1초 규칙(25-1)과 화면 구성(27번)은 이 문서 4·5번으로 옮겨 그대로 유지한다.
- **데이터 기록**: [성과 기록](performance-log.md)의 「Shorts」와 「Shorts → 본편 유입」 표.

## 0. 목적

**채널의 주력은 롱폼이다. 쇼츠의 목적은 "궁금하게 만들어서 롱폼으로 보내는 것"이다.**

쇼츠의 성공은 조회수가 아니라 **본편 유입**으로 판단한다. 조회수가 많아도 본편으로 오는 사람이 없으면 목적을 이루지 못한 것이다.

## 1. 쇼츠 한 편의 구조: 작은 답 + 큰 질문

```
0초   제목의 질문(글자 + 첫 음성) ── 스와이프를 막는다
~20초 작은 질문에 대한 답 ──────── "이 채널은 답을 준다"는 신뢰
끝    본편의 질문 + 본편 썸네일 화면 ─ 궁금증을 본편으로 넘긴다
```

1. **작은 질문 하나에 답한다.** 답을 숨기고 「答えは本編で」로 유도하지 않는다. 답을 받지 못한 시청자는 실망해서 본편도 누르지 않고, 초반에 넘겨 버린다.
2. **본편의 최종 답·중간 반전은 쇼츠에서 말하지 않는다.** 쇼츠의 답은 본편의 **앞쪽 보상(REWARD 1~2)이나 숫자 하나**에서 고른다. 본편의 FINAL ANSWER와 MID REVEAL은 본편에만 둔다.
3. **마지막 한 줄은 "본편의 질문"이다.** 쇼츠의 답에서 자연스럽게 생기는 더 큰 질문이고, **본편의 제목 또는 썸네일 질문과 같은 말**을 쓴다. 링크를 누른 사람이 본편 썸네일을 보고 "아, 이 질문의 답이구나"라고 바로 알아보게 하기 위해서다.
4. **본편에 답이 있는 질문만 던진다.** 본편이 답하지 않는 질문으로 끝내면 신뢰를 잃는다.

## 2. 마지막 2초: 본편을 알아보게 한다 (v1 변경)

지금까지는 마지막 컷이 첫 화면 배경으로 돌아가 **반복 재생**되게 했다. 목적이 본편 유입이므로 바꾼다.

- 마지막 2초는 **본편 썸네일과 같은 물체 + 본편의 질문(글자)** 을 멈춘 화면으로 보여 준다. 예: CASE #004라면 드럼 세탁기 창 + 「何を買ってる？」.
- 「続きは本編で」「リンクから」 같은 광고 문구는 쓰지 않는다(광고처럼 보이면 넘긴다). 질문과 그림만으로 본편을 가리킨다. 쇼츠 화면의 「関連動画」 링크가 그 아래에 있다.
- 첫 화면으로 돌아가는 반복 재생 연출은 쓰지 않는다. 반복 재생은 조회수·시청 시간에는 유리할 수 있지만, 마지막 화면에서 본편을 떠올릴 틈을 없앤다.
- **이 변경은 가설이다.** 본편 유입(関連動画 클릭률)을 이전 쇼츠(반복 재생형)와 비교해 확인한다(8번).

## 3. 한 CASE에 몇 편: 입구 0~1편 + 필요할 때 실험 (2026-09-26 개정)

**롱폼에 집중한다. 쇼츠는 정기적으로 여러 편 만들지 않는다.**

근거(성과 기록):
- #001 쇼츠 두 편은 합쳐 약 1,500회 조회됐지만, #001 본편 유입 경로에 「Shorts 피드」가 없다. 쇼츠 유입이 섞여 있을 수 있는 「기타 YouTube 기능」도 1.9%(약 8회)뿐이다.
- 본편 조회의 약 95~98%는 홈과 추천에서 온다. 본편 조회를 움직인 것은 썸네일·제목의 클릭률이었다(#001 1.6% vs #002 3.3%).
- 쇼츠 한 세트는 롱폼 제작 시간의 상당 부분을 쓴다. 그 시간은 썸네일 A/B안과 롱폼 업로드 주기에 쓴다.

| 종류 | 편 수 | 내용 |
|---|---|---|
| **① 입구** | CASE마다 **0~1편** | 본편 제목의 질문(또는 그 앞 단계)으로 시작 → 본편 REWARD 1 → 본편 썸네일 질문으로 끝(1·2번). 関連動画 지정 |
| **실험** | 필요할 때만 | 다음 CASE의 **주제 후보 검증**(후보 2~3개를 짧은 쇼츠로 올려 계속 시청 비율 비교), 첫 1초 방식 검증 등. 한 번에 한 요소만 바꾼다 |
| 따로 운영(쇼츠 채널화) | 하지 않음 | 시청자층·수익 구조가 롱폼과 다르고, 제작 시간과 채널 정체성이 갈린다 |

- **제작 시간 상한**: 쇼츠에 쓰는 시간은 그 CASE 제작 시간의 **15% 이내**.
- 주제 검증 쇼츠는 쇼츠 시청자와 롱폼 시청자가 다르다는 한계를 두고, 롱폼 결과와 비교해 쓸모를 확인한다.

**다시 판단할 기준**

関連動画를 지정한 쇼츠(CASE #003 3편, 그 뒤의 입구 쇼츠)의 결과로 정한다.

- 쇼츠 한 편당 **関連動画 클릭 20회 이상**, 또는 본편 조회 중 **「Shorts 피드」 5% 이상** → 입구 쇼츠를 CASE마다 2편(① 입구 + ② 의외의 숫자)으로 늘린다.
- 두 CASE 연속 그보다 낮음 → 입구 쇼츠를 중단하고 실험 용도만 남긴다.

## 4. 첫 1초 (성과 지침 25-1 유지)

1. 0프레임에 질문이 글자로 떠 있다(페이드인 없음).
2. 첫 음성은 질문이나 충돌로 시작한다(전제·가격 설명으로 시작하지 않음).
3. 2초 안에 답의 윤곽을 보여 준다.
4. 0프레임부터 큰 움직임이 진행 중이다.
5. 숫자 하나보다 두 숫자의 충돌.

- 쇼츠 제목은 0프레임 글자와 같은 문장으로 한다.
- 확인: 0 / 0.2 / 0.5 / 1.0 / 1.5초 프레임을 소리 없이 보고 질문을 말할 수 있어야 한다.

## 5. 화면과 소리

- 1080×1920. 롱폼 그래픽을 가운데에 넣지 않고 세로 화면을 새로 설계한다.
- 핵심 글자·숫자는 세로 위치 약 20~65%에 둔다. 아래쪽 약 25%와 오른쪽 가장자리는 UI가 가린다.
- 의미를 전하는 글자는 1080 폭 기준 44px 이상. 출처 표기만 30px 허용.
- 머리말(「CASE #00X」)과 엔드카드는 쓰지 않는다. 왼쪽 위 작은 로고만.
- 길이 25~40초. 내레이션은 본편보다 빠르게(현재 1.3배, 9번에서 재검토).
- 실사 없음(CASE #010까지). 본편과 같은 그림(물체·색)을 써서 본편과 같은 채널로 보이게 한다.

## 6. 올리는 순서

1. **본편을 먼저 공개한다.** 쇼츠의 「関連動画」는 공개된 영상만 지정할 수 있다.
2. 쇼츠마다 「関連動画」에 본편을 지정한다.
3. 공개 시점: 입구 쇼츠는 **본편 공개 당일~다음 날**. (2편으로 늘리게 되면 두 번째는 3일째)
4. 설명란 첫 줄에 본편의 질문, `【本編】` 줄에 본편 URL. 고정 댓글에도 본편 링크.
5. 성과가 좋은 과거 CASE는 새 쇼츠(①·② 역할)를 추가로 만들어 다시 입구를 연다.

## 7. 제목·설명

- 제목: 0프레임 질문과 같은 문장 + `#Shorts`. 핵심 검색어(가게·상품 이름)를 앞에.
- 설명란 첫 두 줄: 쇼츠의 답 한 줄 → 본편의 질문 한 줄. 그다음 `【本編】` + URL.
- 해시태그 3~5개. 크레딧·출처는 설명란 끝에.

## 8. 지표와 실험

| 순위 | 지표 | 보는 곳 |
|---|---|---|
| 1 | **関連動画 클릭 수 / 클릭률(클릭 ÷ 조회수)** | Studio → 해당 쇼츠 → 분석 |
| 1 | 본편 트래픽 소스 중 **「Shorts 피드」 조회수** | Studio → 본편 → 분석 → 도달범위 |
| 2 | 계속 시청 / 이탈 | 쇼츠 분석 → 참여도 |
| 3 | 조회수, 평균 시청 시간 | 참고만 |

- 한 번에 한 요소만 바꾼다(첫 화면, 첫 질문 종류, 마지막 2초 등).
- **첫 실험 계획**: CASE #004 쇼츠부터 2번(마지막 2초 = 본편 썸네일 화면)을 적용하고, CASE #003 쇼츠(반복 재생형)와 関連動画 클릭률을 비교한다.
- 3번의 「다시 판단할 기준」으로 편 수를 정한다.

## 9. 아직 정하지 않은 것

- 내레이션 속도(1.3배): 쇼츠만 걸러 본 시청자 연령 데이터가 나오면 다시 본다.
- 쇼츠 길이의 최적값: 본편 유입과 계속 시청 비율을 함께 보고 정한다.
